# Дизайн: Команды (Teams) в UI — переключатели ПД, accessKey, примеры curl/fetch

Дата: 2026-09-23
Статус: согласован (brainstorming)

## Цель

Переименовать «системы» в «команды» (teams) в UI и расширить карточку команды:
переключатели обнаружения разных типов ПД, генерация accessKey, примеры
использования через curl и fetch (маскирование + демаскирование).

## Решения (из уточнений)

- Переименование **только в UI** (заголовки, текст). API/БД/код остаются `systems`.
- Главная = одна вкладка Teams (список команд + создание).
- Переключатели ПД — по `known_types` (из `GET /v1/config`); включённые = в `pii`.
- Примеры curl/fetch — маскирование и демаскирование через `/process` с `X-API-Key`.
- Подход B: вынести карточку команды в отдельный компонент `TeamCard`.

## Компоненты

- `web/src/TeamsTab.tsx` — главная вкладка (список команд + создание). Переименование `SystemsTab.tsx`.
- `web/src/TeamCard.tsx` — карточка одной команды (переключатели ПД, accessKey, примеры).
- `web/src/App.tsx` — рендерит `<TeamsTab />`, заголовок «Команды».
- `web/src/api.ts` — `getConfig()` уже возвращает `known_types`; новых методов не требуется.

## TeamCard

1. **Заголовок** — имя команды + switch `enabled` (вкл/выкл доступ).
2. **Переключатели ПД** — список `known_types` с тумблерами; включённые = в `pii`.
3. **Секция accessKey** — показать ключ (если есть), кнопка «Новый ключ» (regenerate), копирование.
4. **Секция «Примеры»** — curl + fetch для маскирования и демаскирования через `/process` с `X-API-Key`.

## Логика переключателей ПД

- `known_types` из `GET /v1/config` (ФИО, ПАСПОРТ, ТЕЛЕФОН, EMAIL, КАРТА, ИНН, ДАТА, СНИЛС и т.д.).
- У команды `pii []string` — список включённых типов. **Пусто = все типы**.
- Состояние тумблера: если `pii` пусто → все ON; иначе ON только для типов из `pii`.
- Переключение OFF типа X:
  - если `pii` пусто → новый `pii` = все known_types минус X.
  - если `pii` не пусто → новый `pii` = текущий `pii` минус X.
- Переключение ON типа X:
  - если `pii` пусто → ничего (уже все ON).
  - если `pii` не пусто → новый `pii` = текущий `pii` плюс X. Если покрывает все known_types → отправить пустой `pii`.
- Обновление через `api.updateSystem(name, { pii })`.

## Примеры curl/fetch

Для каждой команды с accessKey генерируются примеры (подставляются `<accessKey>` и `<team>`).

**Маскирование:**
```bash
curl -s -X POST http://localhost:8080/process \
  -H "X-API-Key: <accessKey>" \
  -H 'Content-Type: application/json' \
  -d '{"payload":"паспорт 4509 123456","payload_id":"demo1","system":"<team>"}'
```
```js
fetch('http://localhost:8080/process', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', 'X-API-Key': '<accessKey>' },
  body: JSON.stringify({ payload: 'паспорт 4509 123456', payload_id: 'demo1', system: '<team>' })
})
```

**Демаскирование:** тот же запрос, но `payload` = результат маскирования (маска), тот же `payload_id`.

## UX

- Кнопка «Новый ключ» (regenerate) — показывает новый accessKey один раз, с копированием.
- Если `api_key_set: false` — «Ключ не задан» + кнопка «Сгенерировать ключ».
- Примеры показываются только если ключ есть.

Только UI-терминология и компоненты.

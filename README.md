# Модуль безопасности персональных данных (pii-module)

Сервис-прокси между системами-потребителями и LLM. Выполняет **идентификацию** персональных
данных (ПД), их **маскирование** перед отправкой в LLM и **демаскирование** ответа.
Спроектирован для высоких нагрузок: RPS 1000+ при latency < 1 c, обработка текстов до 100 000 символов.

## Архитектура

```
Система-потребитель
      │  POST /process {payload, payload_id}
      ▼
┌─────────────────────────────────────────────┐
│              pii-module                     │
│                                             │
│  ┌──────────┐   ┌──────────┐   ┌─────────┐  │
│  │ Детектор │ → │  Маскер  │ → │  Store  │  │
│  │ (regex)  │   │ [ТИП]    │   │ (Redis) │  │
│  └──────────┘   └──────────┘   └─────────┘  │
│       │              │              │       │
│  идентификация   маскирование   соответствие │
│       │              │          payload_id  │
│       ▼              ▼              ▼       │
│  ┌──────────────────────────────────────┐   │
│  │  HTTP /process  +  /metrics  +  /health│  │
│  └──────────────────────────────────────┘   │
└─────────────────────────────────────────────┘
      │
      ▼  замаскированный текст
   LLM (без доступа к ПД)
      │
      ▼  ответ
┌─────────────────────────────────────────────┐
│  Демаскирование по payload_id (Redis)       │
└─────────────────────────────────────────────┘
      │
      ▼  исходный текст
Система-потребитель
```

**Принцип работы:**
1. **Маскирование** (новый `payload_id`): детектор находит ПД → маскер заменяет на `[ТИП]` →
   оригинал сохраняется в Redis по `payload_id` → возвращается замаскированная строка.
2. **Демаскирование** (существующий `payload_id`): по `payload_id` из Redis возвращается
   исходная строка.

## Быстрый старт

```bash
# Локально (нужен Redis)
docker run -d --name redis -p 6379:6379 redis:7-alpine
go run ./cmd/server

# Docker Compose (модуль + Redis + Prometheus)
docker compose up -d --build
```

Проверка:
```bash
curl -X POST http://localhost:8080/process \
  -H "Content-Type: application/json" \
  -d '{"payload":"паспорт 4509 123456, email test@example.com","payload_id":"test-1"}'
# → {"result":"паспорт [ПАСПОРТ], email [EMAIL]"}
```

## Контракт API

### `POST /process`

Запрос:
```json
{ "payload": "строка", "payload_id": "идентификатор" }
```

Ответ:
```json
{ "result": "строка" }
```

Логика:
- **Новый `payload_id`** → маскирование (payload = исходная строка) → возвращает маску и
  запоминает соответствие в Redis.
- **Существующий `payload_id`** → демаскирование (payload = маска) → возвращает исходную строку.
- Ответ всегда `{"result": "..."}`.

Коды ответов:
- `200` — успех
- `400` — невалидный запрос (нет `payload_id`, битый JSON)
- `429` — превышен rate limit (с заголовком `Retry-After`)
- `500` — внутренняя ошибка

### `GET /health`
Возвращает `ok`.

### `GET /metrics`
Prometheus-метрики.

## Конфигурация (env)

| Переменная | По умолчанию | Описание |
|-----------|--------------|----------|
| `PORT` | `8080` | Порт HTTP-сервера |
| `REDIS_URL` | `redis://localhost:6379/0` | URL Redis для хранения соответствий |
| `STORE_TTL_HOURS` | `24` | TTL хранения соответствий (часы) |
| `ALLOW_UNMASK` | `true` | Разрешить демаскирование |
| `RATE_LIMIT_RPS` | `0` (выкл) | Макс. запросов/сек (429 при превышении) |
| `RATE_LIMIT_BURST` | `= RPS` | Ёмкость token-bucket |

## Идентифицируемые типы ПД

| Тип | Плейсхолдер | Пример |
|-----|-------------|--------|
| ФИО | `[ФИО]` | Иванов Иван Иванович |
| Дата рождения | `[ДАТА]` | 15.03.1990, 15 марта 1990 года |
| Место рождения | `[МЕСТО_РОЖДЕНИЯ]` | место рождения: г. Москва |
| Паспорт | `[ПАСПОРТ]` | паспорт 4509 123456 |
| Гражданство | `[ГРАЖДАНСТВО]` | гражданство: Российская Федерация |
| Орган выдачи | `[ОРГАН]` | выдан ОВД района Хамовники |
| Код подразделения | `[КОД_ПОДРАЗДЕЛЕНИЯ]` | код подразделения 770-001 |
| Водительское удостоверение | `[ВУ]` | водительское удостоверение 77 12 345678 |
| Загранпаспорт | `[ЗАГРАНПАСПОРТ]` | загранпаспорт 71 1234567 |
| Военный билет | `[ВОЕННЫЙ_БИЛЕТ]` | военный билет 77 12 345678 |
| Свидетельство о рождении | `[СВИДЕТЕЛЬСТВО_О_РОЖДЕНИИ]` | свидетельство о рождении 77 12 345678 |
| Адрес | `[АДРЕС]` | адрес: г. Москва, ул. Тверская, д. 1, кв. 5 |
| Email | `[EMAIL]` | test@example.com |
| Телефон | `[ТЕЛЕФОН]` | +7 912 345-67-89 |
| ИНН | `[ИНН]` | ИНН 7707083893 |
| Номер карты | `[КАРТА]` | карта 4276 1234 5678 9012 |
| CVV | `[CVV]` | cvv 123 |
| ПИН | `[ПИН]` | пин 1234 |
| Имя держателя карты | `[ДЕРЖАТЕЛЬ]` | держатель карты: Иван Петров |

**Особенности:**
- **Регистронезависимость** — все правила `(?i)`.
- **Форматы дат** — `дд.мм.гггг`, `мм.дд.гггг`, `гггг.дд.мм`, текстовые («15 марта 1990 года»).
- **Контекстное различение** — паспорт vs ВУ vs военный билет по ключевым словам.
- **«Пушкин — не ПД»** — ФИО/адрес маскируются только в ПД-контексте, не как литературные упоминания.
- **Контекстное маскирование** — ПИН/CVV маскируются только при наличии другого типа ПД
  (например, «пин 1234» не маскируется, «пин 1234, карта 4276...» — маскируется).

## Расширение списка ПД

Новый тип добавляется без переписывания ядра:
1. Добавить константу типа в `internal/detector/types.go`.
2. Добавить правило в `internal/detector/rules.go` (regex или capture-правило с ключевым словом).

## Метрики (Prometheus)

| Метрика | Тип | Описание |
|---------|-----|----------|
| `pii_requests_total{type,status}` | Counter | Кол-во запросов по направлению (mask/unmask) и статусу |
| `pii_latency_seconds{type}` | Histogram | Latency запросов |
| `pii_detected_total{type}` | Counter | Кол-во обнаруженных ПД по типам |

## Логирование

Структурированные JSON-логи (slog). По каждому запросу логируются `payload_id`, обнаруженные
типы ПД, latency — **без утечки самих значений ПД**:
```
INFO process: masked payload_id=test-1 types=[ПАСПОРТ EMAIL] latency_ms=1
```

## Безопасность

- **Нет утечек ПД** — payload никогда не логируется, метрики считают только типы.
- **Деградация при недоступности Redis** — маскирование работает (stateless), демаскирование
  возвращает payload без изменений (fail-open).
- **Rate limiting** — защита от перегрузки (429 + `Retry-After`).
